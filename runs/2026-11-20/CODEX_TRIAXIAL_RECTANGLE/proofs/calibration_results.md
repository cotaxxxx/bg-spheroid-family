# 三軸主矩形の有限箱較正：実測、費用、残領域

2026-11-20

**DIAGNOSTIC_ONLY / NOT_EVIDENCE**

## 1. 対象と記録の位置づけ

形を L=diag(1,s,st)、主矩形を R=[1,16/5]×[1,6] とする。開八分体・面13・面23で G3=E3/q3、面12で D12=(G2−G1)/(s²−1) を扱う。ここでは、事前固定した有限幅の形状箱・位置箱における外向き区間評価の幅と費用を較正した。

この記録は全主矩形と全位置領域の被覆ではない。下端が正になった有限パッチ、未決の試験、未処理の領域を分けて残す。全体の扱いは DIAGNOSTIC_ONLY / NOT_EVIDENCE のままとする。

集計の原データは [calibration_summary.json](../out/calibration_summary.json)、原本C核との非区間照合は [calibration_reference.json](../out/calibration_reference.json) にある。全台帳の判定は、記録した下端から検査器が再計算した。

区間計算はIEEE754 binary64の基本演算・平方根をnextafterで外側へ広げる。球面積分は角度セル全域の範囲に正の測度を掛けた和で、点求積を区間包囲に読み替えていない。πは有理交代級数、角度核は有理係数の級数と剰余で包んだ。計算環境の通常の丸め・基本演算・平方根・段階的アンダーフローを仮定する。これらの算術を別の形式系で検証したという意味ではない。

凍結した核の説明は [calibration_notes.md](calibration_notes.md) にある。本結果報告の追加に当たり、そのファイル、計画、実行済みコードは変更していない。

初回の空台帳の実在ファイル名は **[calibration_pilot.csv](../out/calibration_pilot.csv)** である。ヘッダーのみで数値行は0件。成功した台帳には数えない。

weight=Box(4)/pi_box()/denへの1行修正をC1Aとして別記録し、計画・コードSHAを実行前に保存した。数学上の対象、角度格子、停止規則は変更していない。検査器はC1の記録上のcode/calibration.pyのhashを、保存されたcode/calibration_c1_initial.pyへ履歴対応させる。C1A以降のcalibration.pyとは区別する。

shape31、中心(s,t)=(3.1875,5.984375)、面12の位置中心(1/2,1/2,0)では、nmu=512で

を得た。後述の原本C核の640次点評価は0.02812889742502009である。

台帳は [calibration_pilot_c1a.csv](../out/calibration_pilot_c1a.csv) の4行と [calibration_remaining_c1a.csv](../out/calibration_remaining_c1a.csv) の191行。検査器が作る統合版は [calibration_c1a_all.csv](../out/calibration_c1a_all.csv) である。

### 3.2 C2：形幅と球面境界

shape ID 0,7,24,31の4隅で、形の各半幅を2^-8,2^-6,2^-4に拡大した48箱はすべて下端が正だった。最大半幅2^-4の16箱では、最終nmuは128が5件、256が9件、1024が2件。形幅試験全体の最小下端は0.004586183710789778である。

範囲は下端s,t=1、上端t=6で切った。上端sには16/5を外側へ包む二進数209716/65536=3.20001220703125を使う。これは16/5より0.00001220703125大きく、Rとの交差を覆う外側の二進包囲である。全幅1/8をすべての試験箱で保ったわけではない。

別の16位置箱は、(2/3,1/3,2/3),(3/5,0,4/5),(0,3/5,4/5),(3/5,4/5,0)の各球面点を含む。これらもすべて下端が正で、15件がnmu=128、1件が256だった。境界群の最小下端は0.002186518369949939。

境界での対象は位置箱Bと閉球Dの共通部分であり、箱B全体が球内という主張ではない。D²が0を含む角度セルは、|A3 v3/D|≤st、|v1v2/D²|≤1/(2s)、|xi1 xi2/(A1A2B)|≤1/(2s)とgamma∈[0,1]の既知範囲で包む。接触点は球面積0で、セル全体の有界包囲を積分する。safeD2は配列計算を可能にする作業用値であり、そのセルで必要な比は既知範囲へ置き換える。ゼロ除算の数値代用を結果には採用していない。

台帳は [calibration_extended.csv](../out/calibration_extended.csv)、根拠と固定条件は [PLAN_CALIBRATION_C2.md](../plans/PLAN_CALIBRATION_C2.md) にある。

### 3.3 C3：位置幅と直接カラー

形の公称半幅1/16を保ち、位置の非零座標を広げた結果は次のとおり。

| 位置の全幅 | 下端が正 | 未決 |
|---|---:|---:|
| 1/128 | 14/16 | 2/16 |
| 1/32 | 5/16 | 11/16 |
| 1/8 | 0/16 | 16/16 |

全幅1/128で残った2件はshape7・31のD12。G3の12件は下端が正だった。全幅1/32の成功5件はshape0のD12とshape24の4モードである。広げた位置箱では、角度格子だけを細かくしても入力箱による幅が残る。

直接カラーは、G3でq3∈[1/256,3/256]、D12でq1∈[1/256,3/256]とした16件。形の半幅はC1Aの2^-12へ戻し、他の非零位置座標の半幅を1/256にした。16件すべてnmu=1024でも未決である。高異方性のG3の最大最終幅は491.10202930054123だった。

これは実際のG3の値がゼロに近いと確認した結果ではない。直接除算と区間依存によって包囲が広がることを示す実測である。台帳 [calibration_position.csv](../out/calibration_position.csv) と、上限・未処理記録 [calibration_position_run.json](../out/calibration_position_run.json) を保存した。

### 3.4 C4：鏡映によるG3の正規化

鏡映対称性E3(q1,q2,0)=0と微分の基本定理から、q3>0では

    E3(q1,q2,q3)/q3 = integral_0^1 H33(q1,q2,u*q3) du.

したがって、q3∈[0,3/256]のH33の包囲は、同じ横位置でq3∈(0,3/256]のG3を包む。q3除算を数値的に行わない。

shape0,7,24,31の各3モードを計画した。形の半幅は2^-12、q1,q2の非零座標の半幅は1/256。shape0・24の計6箱はnmu=128で下端が正、shape7・31の高異方性6箱はnmu=2048で未決。成功箱の最小下端は0.5472396005014584だった。

原本式(1)のHessianを使い、非負因子を

    A3-b3² = A3*(v1²+A2*v2²)/D²

として保持した。角度核Qにはz=(1−gamma)/2、a_n=4^n(n!)²/(2n+1)!を用いた正項級数

    Q = sum_n 2*a_n*(n²+5n+5)/(2n+3) * z^n

を使う。Qはgammaについて減少する。80次の残部は0以上2*(80+4)/2^80以下として包んだ。詳細は [PLAN_CALIBRATION_C4.md](../plans/PLAN_CALIBRATION_C4.md) にある。

台帳は [calibration_normalized.csv](../out/calibration_normalized.csv)、上限記録は [calibration_normalized_run.json](../out/calibration_normalized_run.json)。この変更だけで高異方性の全カラーを解消したとはしていない。

## 4. 検査と原本照合

### 4.1 C5：全台帳の検査

[calibration_check.py](../code/calibration_check.py) は整数端点、予定ケース、格子段の順序、停止規則、全件数、時間上限と未処理件数を再検査する。positiveという文字列ではなく、記録した下端から判定を再計算する。

全計画のSHAも検査する。初回C1だけは、記録上のcode/calibration.pyを履歴ファイルcode/calibration_c1_initial.pyへ対応させ、その対応をJSONに出す。結果はintegrity_status=consistentである。

実装の点検として、πと固定した8個のgamma格子点でP,F,R,J,K,Qの包囲がmpmath90桁の値を含むことを確認した。これは全格子点の形式的検証の代用ではない。

区間核・有理w座標・角度表を使わない別Python点求積でも20点を計算し、80・160次の値が記録区間内にあることを確認した。ただし、高異方性のC4 shape31では80→160次に0.12503008356751666の差があった。この差を残し、点求積の収束保証とは扱わない。

またC1A shape31のD12、C2 shape31の境界D12、C4 shape0のG3_123の最終段を同じ区間コードで再実行し、数値端点のビット一致を確認した。同じコードの再実行は再現性の確認であり、独立数学監査とは区別する。

## 5. Judge判断用の固定格子費用表

形の全幅を仮に1/8とすると、Rの格子はceil((11/5)/(1/8))×ceil(5/(1/8))=18×40=720箱となる。位置の全幅をh=1/nとし、第一八分体を含む単位立方体n³箱と、3面の3n²箱を数える。仮想ケース数は720*(n³+3n²)である。

これに、C3でその位置幅を使った16ケースの「全段の評価時間」の中央値を掛ける。未決ケースの測定時間も含む。

| 位置の全幅 | 下端正 | ケース時間中央値 | 仮想総ケース数 | 逐次相当の評価日数 | 理想的な2ワーカー日数 |
|---|---:|---:|---:|---:|---:|
| 1/128 | 14/16 | 0.138311秒 | 1,545,338,880 | 2,473.808日 | 1,236.904日 |
| 1/32 | 5/16 | 1.703702秒 | 25,804,800 | 508.839日 | 254.420日 |
| 1/8 | 0/16 | 1.840362秒 | 506,880 | 10.797日 | 5.398日 |

この表は固定格子の仮定の下での費用算術であり、全域完了時間の予測・上界ではない。特に次の限界がある。

- 形の4隅では幅をRで切断している。全720形状箱で全幅1/8が機能すると確認したわけではない。
- 広い位置箱には既に未決例がある。安価に見える全幅1/8は16件すべて未決であり、その費用を完了費用と解釈できない。
- 球外の立方体セルは除外できるが、軸や境界のカラーへの追加作業は別に必要である。
- 適応細分での箱数削減と、未評価部分の停止深さは不明である。適応法の全域費用は今回推定していない。
- 2ワーカー欄は理想的に半分にした値であり、実際の並列効率・運用費を測定した予測ではない。

したがって、C1Aの128件の速度だけを全域へ比例外挿する設計には根拠が足りない。今回の実測は、形と位置の依存を保つ評価、角度セルの適応化、カラーの別核を次に較正するための判断材料である。

## 6. 残領域の定義

位置層を次のように定める。

    D123 = {q1,q2,q3>0, |q|<=1}
    D13  = {q1,q3>0, q2=0, |q|<=1}
    D23  = {q2,q3>0, q1=0, |q|<=1}
    D12  = {q1,q2>0, q3=0, |q|<=1}

モードmの記録行rの形箱をS_r、位置箱をB_r、区間下端をL_rとすると、今回その核の下端が正になった有限パッチを

    U_m = union_{r: mode=m, L_r>0} ((S_r intersect R) × (B_r intersect D_m))

とする。C4の成功行は、G3についてq3∈(0,3/256]と解釈して加える。核の正値判定が未処理なのは

    (R × D_m) minus U_m

である。shapeへの射影が正の箱に入っていても、その形の全位置を処理したとは限らない。中心・座標軸の別分類もこの較正の対象外である。

### 6.1 q3=0と近軸カラー

C4でq3=0に得るのはG3の連続延長である。q3=0ではE3=0なので、その面の停留点をG3の正値だけで排除しない。

C4の成功した6横位置パッチ以外のq3→0カラーは未処理である。高異方性の6箱は未決を残した。D12のq1カラー4箱も未決で、q1q2=0の軸と任意に近い領域の一般的な被覆にはなっていない。

### 6.2 s=1の対称辺

C2の一部の有限形状箱はs=1を含む。D12はA2−A1での数値除算を使わない因数除去済み核で、その連続延長の正値を扱える。

しかしG2−G1=(s²−1)D12である。s=1そのものではD12>0からG2−G1>0や停留点排除は従わない。D12の正値による面12の軸外排除は、U_12のうちs>1の部分に限る。対称辺上は別の分類が必要で、s→1の未評価横位置や形状の残りも未処理である。

### 6.3 球面境界

C2の16個の境界パッチは下端が正だったが、球面境界全体を被覆していない。その残りは上の集合差に含める。接触セルを処理できたことと、全境界の費用を測ったことを区別する。

## 7. 再現手順

packageを作業ディレクトリとして次の順に実行する。Python環境にはNumPy、SciPy、mpmath、Cコンパイラが必要である。実測時のPython・NumPy・プラットフォームはcalibration_summary.jsonに記録している。

```bash
python code/calibration.py --start 0 --stop 1 --workers 1 --output calibration_pilot_c1a.csv
python code/calibration.py --start 1 --stop 32 --workers 2 --output calibration_remaining_c1a.csv
python code/calibration_extended.py --workers 2
python code/calibration_position.py
python code/calibration_normalized.py
python code/calibration_check.py
python code/calibration_reference.py
```

各計画はplans/PLAN_CALIBRATION*.md、事前SHAは対応する.sha256である。checkerはC1Aの2台帳を統合してcalibration_c1a_all.csvを作る。C6はこれと同梱のinputs/TRIAXIAL_FIRST_ATLAS_20261120.zipを読む。

再実行で時間は変わる。端点・判定・件数と時間を別に比較する。計画を変更して改善を試す場合は、別計画を実行前に固定し、ここに記録した未決ケースと条件を上書きしない。
