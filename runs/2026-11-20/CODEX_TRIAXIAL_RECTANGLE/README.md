## 環境

実測環境はPython 3.12.14、NumPy 2.3.5、SciPy 1.17.0、mpmath 1.3.0。通常の64ビットIEEE 754基本演算・平方根、最近接丸め、段階的アンダーフローを前提にする。原本の非区間C核との照合には `gcc` と `cc` が必要。ネットワーク接続、GitHub操作、研究PC接続は不要。

## 再現

```sh
./reproduce.sh --check
./reproduce.sh --rerun
```

実行権限が保持されない場合は `bash reproduce.sh --check` とする。Pythonの場所を変える場合は `PYTHON=/absolute/path/to/python bash reproduce.sh --check` を使う。

`--check`（省略時も同じ）は、配布物のSHA-256、元ZIP内部の54項目、中心・軸・較正の台帳構造、符号、固定計画、指定帯の被覆、記録した少数の再評価・非区間照合を確認する。解析証明の数学的な正しさや未処理領域を機械検証するものではない。

`--rerun` は、数値を出す前に停止した初版を除き、A1以降の固定計画を順に再実行してから同じ検査を行う。途中の未決段階も作り直す。最大2ワーカーを使う計画があるが、計画同士は同時に走らせない。C3/C4と軸拡張の事前上限は実行コードにも残っている。

どちらのモードも、最初に配布元のhashを照合し、パッケージを新しい一時ディレクトリへ複製する。元の配布台帳は上書きしない。原本ZIPも安全に一時ディレクトリへ展開し、そこでC核をコンパイルする。最後に出力される `REPRODUCTION.json` に各コマンド、終了コード、時間、出力場所がある。

時間列や実行環境の文字列は変わり得るので、再実行後のファイルhashは配布時と同じとは限らない。核と計画のhash、整数端点、格子、包含、符号、および未決の保持を比較する。同一環境での指定3ケースの区間再評価は、端点のビット一致も検査する。

## 台帳の読取り

中心の端点は `slo_i,shi_i,tlo_i,thi_i` を `scale` で割る。軸は `s0,s1,t0,t1` を `shape_den`、半径 `r0,r1` を `r_den` で割る。軸外較正は `slo,shi,tlo,thi,q1lo,...,q3hi` を `unit=65536` で割る。全て閉区間の整数端点である。

`lower,upper` は外向き包含の両端。正の下端があれば、その記録した箱に対する正符号を言える。途中の未決行と最終行を混同しない。境界箱は閉球との交差、Rの端を外側へ丸めた形状箱はRとの交差を対象にする。

同じ箱を細かい角度格子で何度か評価しているため、行数は被覆領域数ではない。ケースにも重複がある。`calibration_c1a_all.csv` は最初の二つのC1A台帳の統合コピーなので、費用を二重計上しない。軸の一回の評価からg・Hessian・U'の複数行が出るので、時間は評価単位で数える。

初期版のhashは、中心では `center_interval_A_original.py`、軸外では `calibration_c1_initial.py` に対応する。履歴上の記録パスが現行版と同じでも、検査器が明示した保存先へ対応させる。古い計画のhashを変更してはいない。

## 主張の限界

正のG3からE3の非零を言えるのは q3≠0。正規化カラーのq3=0ではG3の延長値を得るだけである。面12の差商D12が正でも、s=1ではG2−G1=(s²−1)D12=0なので停留円を排除できない。軸の一意性は明記した半径帯の内部だけである。

費用表は仮想の固定格子の積算であり、全域証明の完了予算ではない。別の核による厳密な抜き取り監査、四曲線の全域検証、残る形状・位置・境界の排除は未了である。
