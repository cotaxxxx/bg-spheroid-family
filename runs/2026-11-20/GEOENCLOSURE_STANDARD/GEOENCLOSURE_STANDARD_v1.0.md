# GeoEnclosure 基準 v1.0

2026-11-20 ／ 起草：chat ／ 方法論の命名：Judge

方法論 GeoEnclosure で、数学の主張を「区間計算で確かめた」と言うための基準である。回転楕円体族と三軸楕円体の停留点の研究（V48〜V59）で実際に使い、誤りを見つけた経験から決めた。道具は GeoEncloseReader である。

---

## 0. 原則

GeoEnclosure の主張は、次の四段で成り立つ。

1. **形に合う表示：** 被積分関数が有界になる見方に置き直してから計算する。弦の表示、極を中心にした地図、境界のトレースがその例である。
2. **包んで符号を決める：** 標本の値ではなく、丸めまで含めて真の値を必ず含む区間で、各箱の符号を確定させる。
3. **空から再生成し、独立に照合する：** 作った人とは別の式、別のコードで同じ符号を確かめる。
4. **解析で閉じる：** 有限個の箱の結果を、単調性、対称性、微分の上界などの証明で、族全体の結論につなぐ。

**数値の標本、図、最小二乗の探索は、どれだけ多くても診断であり、証明ではない。**

---

## 1. 判定の語

| 語 | 意味 |
|---|---|
| DIAGNOSTIC_ONLY / NOT_EVIDENCE | すべての報告の既定の扱い。Judge が採用するまで変わらない |
| CONFIRMED | 箱の全体で、主張した符号を区間で確かめた |
| NOT_REPRODUCED | 予算の中で符号が出なかった。**反例ではない** |
| CONTRADICTED | ある箱で、区間が主張と逆の符号に完全に入った。直ちに報告する |
| 採用 | Judge だけが決める。§7 の条件を満たしたものに限る |

## 2. 計算の基準（包みが正しいための条件）

### 2.1 丸め
- 四則と平方根は、結果の端を外向きに丸める（arb の球、または binary64 で 1 ulp 外へ動かす）。
- 三角関数、π、級数の係数は、保証のないライブラリで区間の端に評価しない。高精度の値か厳密な有理数から、外向きに丸める。
- 多数の項の和は、丸めの誤差まで含めて包む（例：fsum の後に 1 ulp 外へ動かす）。
- 端点から計算する。幅の広い区間の二乗や共通部分で、0 未満や NaN を出さない。

### 2.2 求積の剰余
次のどれかで、剰余を明示して包む。
- **値域の包み（一次）：** セルの上の被積分関数の値域 × セルの測度。
- **平均値形式（二次）：** セルの中心の値 × 測度、勾配の中点 × 一次モーメント、勾配の半径 × |x − x_c| のモーメント。
- **解析的な剰余：** スペクトル近似などで、剰余の上界を証明して加える。その証明は §5 の手による照合の対象になる。

**数値の求積の値を、剰余なしに区間として使わない。** Taylor の打ち切りを厳密な式として使わない。これは V51 の訂正 E2 の教訓である。

### 2.3 特異点と接触
- 被積分関数が有界でないところには、先験的な上界にセルの測度を掛ける。上界の導出は、核の文書に書く。
- 点の値を恣意的に割り当てない。

### 2.4 有効な範囲
- 真の値が入っていると分かっている範囲（例：γ ∈ [0, 1]）でだけ、区間を切り詰めてよい。その根拠を書く。
- 箱が定義域からはみ出すときは、主張する範囲（例：箱と閉球の共通部分）と、平均値の線分がその範囲にとどまることを示す。

### 2.5 級数
- 正項の級数を使い、尾を明示した上界で包む。項の比の上界を書く。

## 3. 手順の基準

- **計画を実行前に固定する。** 計画、抜き取りの選び方、コードのハッシュを、実行の前に記録する。
- **変更は新しい計画にする。** 実行の途中で方法を変えたら、改訂版（例：V55-A、V58-E）として残し、元の記録を消さない。
- **符号や値を見て方法を選ばない。** 診断の問いは二択にする。
- **決まらなかった行も、失敗した出力も全部残す。**
- **予算を決める。** 1 箱あたりと全体の CPU 秒を、計画に書く。

---

## 4. 台帳の基準

- **箱の端：** 整数か有理数で書く。分母を明記する（例：2⁻²⁰、5242880）。
- **値：** 区間の下端と上端。単位を明記する（例：2⁻³⁶）。
- **被覆の検査：** 終端の箱が対象の領域を**隙間も重なりもなく**覆うことを、整数で確かめる。面積（体積）の和が領域に等しいことも確かめる。
- **来歴：** 入力の台帳のハッシュを記録し、元の保管物とバイト単位で照合する。
- **移送：** ある辺の台帳を内側へ移すときは、各行の余裕、誤差の式、残りの余裕を、丸める前の分数で残す。

---

## 5. 監査の基準（GeoEncloseReader）

1. **受け取り：** ハッシュを照合する。ZIP は別のディレクトリに展開し、危険なパスを調べる。Python は `-I` で動かし、作った人のスクリプトは写しの上でだけ動かす。
2. **手による照合：** 新しい解析の補題と定数は、全部を手で追う。定数の連鎖は、chat のコードで数値を再計算する。
3. **独立な核：** 作った人のコード、核、係数を使わない。式は自分で導き直す。
4. **抜き取り：** 各区分について、**余裕の最も弱い箱**と、**固定した種による乱数の箱**を選ぶ。
5. **同じ量の確認：** 箱の中心での自分の包みが、作った人の区間と交わることを確かめる。交わらなければ CONTRADICTED として扱う。
6. **符号の確認：** 箱の全体で、主張した符号を自分の包みで確かめる。分割と細かくする規則は、計画に固定する。
7. **被覆と移送の再計算：** §4 の検査を、自分のコードで全件行う。
8. **点の照合：** 節点の値など、点の主張が独立な値を含むかを照合する（例：Claude Code による台帳の点の照合）。

**点の照合だけでは、箱の値域も分類も確かめたことにならない。**

---

## 6. 結果の表記の基準

- **範囲を数で書く。** 例：「1 < s ≤ 1 ＋ 2⁻³⁹」「log(st) ≤ 10⁻⁵」。
- **存在定理と明示的な結果を区別する。** 近傍の大きさが出ていないときは、そう書く。
- **未了の部分を同じ表に書く。**
- **言い過ぎない。** 「閉じた」と書くのは、主張の全範囲で §7 を満たしたときだけにする。
- **誤りは訂正として残す。** 番号（E1、E2…）を付け、元の文を消さない。

---

## 7. 採用の基準

Judge が研究成果として採用できるのは、次のすべてを満たしたものである。

1. 作った人の検査器が通る（ハッシュ、整数の被覆、符号、局所の包含）。
2. 独立な監査で CONTRADICTED が一つもない。最も弱い箱を含む抜き取りで、符号が確かめられている。
3. 新しい解析の補題と定数を、手で確かめてある。
4. 主張の範囲と、未了の部分が明記されている（§6）。
5. 計画、台帳、コード、記録が evidence に保管されている。

採用した後で反例や誤りが見つかったら、訂正として記録し、採用を見直す。

---

## 8. 道具を残す

一つの問題の解答より、次の問題を解くための道具を残す。

- 監査のたびに、核と selftest を GeoEncloseReader に加え、版を上げて保管する。
- 道具の限界と、分かった注意点を README に書く（例：細長い形での赤道の H₃₃）。
- 計算の費用は実測して残す。見積もりは方法に依存するので、どの方法での数かを書く（V58）。
