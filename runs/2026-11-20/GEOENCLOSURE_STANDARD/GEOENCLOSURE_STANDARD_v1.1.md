# GeoEnclosure 基準 v1.1

2026-11-20 ／ 起草：chat ／ 方法論の命名：Judge ／ v1.0 への査読（Claude Code）を反映

GeoEnclosure の方法で、数学の主張を「区間計算で確かめた」と言ってよい条件を定める。回転楕円体族と三軸楕円体の停留点の研究（V48〜V59）で実際に使い、誤りを見つけた経験から決めた。道具は GeoEncloseReader である。

**v1.0 からの主な変更**
- 語を分けた。CONTRADICTED と INCONSISTENT を区別し、箱と補題の状態を表す語も加えた。
- 被覆の条件を、和集合が領域を含むことに改めた。重なりは許し、記録する。
- 「値を見て方法を選ばない」を書き分けた。適応的な細分は、事前に固定した規則の下なら許す。
- 採用を二つの水準に分け、論文での書き方と対応させた。
- 新しい項目を加えた。定義への遡り、点の照合の必須化、余裕の予備、根の主張、主張と台帳の対応表、浮動小数点の環境、境界での微分、公開と人の責任、抜き取りの最小数、適合表。

## 0. 原則

GeoEnclosure の主張は、次の四段で成り立つ。

1. **形に合う表示：** 被積分関数が有界になる見方に置き直してから計算する。弦の表示、極を中心にした地図、境界のトレースがその例である。
2. **包んで符号を決める：** 標本の値ではなく、丸めまで含めて真の値を必ず含む区間で、各箱の符号を確定させる。
3. **空から再生成し、独立に照合する：** 作った人とは別の式、別のコードで同じ符号を確かめる。どこまで照合したかは、§7 の水準で表す。
4. **解析で閉じる：** 有限個の箱の結果を、単調性、対称性、微分の上界などの証明で、族全体の結論につなぐ。

**数値の標本、図、最小二乗の探索は、どれだけ多くても診断であり、証明ではない。**

## 1. 語

### 1.1 報告と箱の状態
| 語 | 意味 |
|---|---|
| DIAGNOSTIC_ONLY / NOT_EVIDENCE | すべての報告の既定の扱い。Judge が採用するまで変わらない |
| CONFIRMED | 監査で、箱の全体について主張した符号を区間で確かめた |
| NOT_REPRODUCED | 監査の予算の中で符号が出なかった。**反例ではない** |
| CONTRADICTED | 監査の区間が、主張と逆の符号に完全に入った。**符号の反例**であり、直ちに報告する |
| INCONSISTENT | 同じ量について、作った人の区間と監査の区間が交わらない。**どちらかの包みか式が誤っている**ことを示す。符号の反例とは限らない。原因が分かるまで、その台帳全体を保留する |
| EMPTY | 箱が主張の領域と交わらない（例：閉球の外）。捨てたことを記録する |
| OPEN | 作った人が未決定とした箱。主張を支えない。未了として数える |

### 1.2 補題の状態
| 語 | 意味 |
|---|---|
| STATED | 作った人が書いただけ |
| HAND_CHECKED | 監査が導出を手で追い、定数を数値で再計算した |
| REDERIVED | 監査が独立に導き直した（同じ結論、または安全側の定数） |
| GAP | 導出に穴がある。穴の位置を書く |

### 1.3 判定
「採用」を決めるのは Judge だけである。水準は §7 による。

## 2. 計算の基準（包みが正しいための条件）

### 2.1 丸めと浮動小数点の環境
次のどれかの方式で、真の値を必ず含む区間を作る。どの方式を使ったかを報告書に書く。
- **(a) 球の演算：** arb など、正しさが保証されたライブラリの球。
- **(b) 最近接丸め ＋ 外向きの補正：** 各演算の結果を 1 ulp だけ外へ動かす。正規数以下の値もこの補正で覆う。
- **(c) 有向丸め：** 丸めモードを上向き（または下向き）に固定して計算する。次の三つを満たすときだけ認める。
  - モードが実行時に実際に効いていることを、検査で確かめる。
  - 各演算の下端と上端を、それぞれ対応する向きで計算する。
  - ライブラリの関数がモードを無視したりリセットしたりしないことを確かめる。

**環境の条件（三つの方式に共通）**
- 融合積和（FMA）への自動縮約を禁止する（例：`-ffp-contract=off`）。
- x87 の拡張精度を使わない（SSE2 などの binary64 で計算する）。
- `-ffast-math` とそれに類するフラグを禁止する。コンパイラ、版、フラグを記録する。
- 10 進のリテラルや、文字列からの読み込みで丸めが起きる。定数は、有理数から外向きに丸めて作るか、誤差を区間に含める。
- 三角関数、π、級数の係数は、保証のないライブラリで区間の端に評価しない。高精度の値か厳密な有理数から、外向きに丸める。
- 多数の項の和は、丸めの誤差まで含めて包む。
- 端点から計算する。幅の広い区間の二乗や共通部分で、0 未満や NaN を出さない。

### 2.2 求積の剰余
次のどれかで、剰余を明示して包む。
- **値域の包み（一次）：** セルの上の被積分関数の値域 × セルの測度。
- **平均値形式（二次）：** セルの中心の値 × 測度、勾配の中点 × 一次モーメント、勾配の半径 × |x − x_c| のモーメント。
- **解析的な剰余：** スペクトル近似などで、剰余の上界を証明して加える。その証明は §5 の手による照合の対象になる。

**数値の求積の値を、剰余なしに区間として使わない。** Taylor の打ち切りを厳密な式として使わない（V51 の訂正 E2）。

### 2.3 特異点、接触、境界での微分
- **有界でない被積分関数：** 先験的な上界にセルの測度を掛ける。上界の導出は核の文書に書く。点の値を恣意的に割り当てない。
- **積分記号下の微分：** 優収束などで正当化する。被積分関数の微分を可積分な関数で一様に抑えることを示す。
- **境界のトレース：** 内側からの延長が連続であることを示す（例：接触点の帽子の積分が一様に O(η)）。そのうえで、境界の値は内側のトレースとして定義する。境界で二階微分の存在を仮定しない（V51、V54 の論法）。

### 2.4 有効な範囲
- 真の値が入っていると分かっている範囲（例：γ ∈ [0, 1]）でだけ、区間を切り詰めてよい。その根拠を書く。
- 箱が定義域からはみ出すときは、主張する範囲（例：箱と閉球の共通部分）を明記する。平均値の線分がその範囲にとどまることも示す。

### 2.5 級数
正項の級数を使い、尾を明示した上界で包む。項の比の上界を書く。

## 3. 手順の基準

- **計画を実行前に固定する。** 計画、抜き取りの選び方、細分と判定の規則、コードのハッシュを、実行の前に記録する。
- **適応は許す。規則は固定する。** 次のことは、規則が事前に固定されていれば許す。区間の包みは、箱の選び方によらず正しいからである。
  - 未決定の箱を分ける。
  - 角度の分割を細かくする。
  - 最初に通った判定を採る。
- **禁止する：**
  - 結果を見てから**主張の範囲**を変えること。
  - 結果を見てから**監査の抜き取り方**を変えること。
  - 結果を見てから**合否の閾値**を変えること。
- **変更は新しい計画にする。** 実行の途中で方法を変えたら、改訂版（例：V55-A、V58-E）として残し、元の記録を消さない。
- **診断の問いは二択にする。**
- **記録を全部残す。** 決まらなかった行も、失敗した出力も残す。
- **予算を決める。** 1 箱あたりと全体の CPU 秒を、計画に書く。

## 4. 台帳の基準

- **箱の端：** 整数か有理数で書く。分母を明記する（例：2⁻²⁰、5242880）。
- **値：** 区間の下端と上端。単位を明記する（例：2⁻³⁶）。
- **被覆：** 終端の箱の**和集合が、主張の領域を含む**ことを、整数で確かめる。
  - 木の台帳では、各親が子の和集合に等しいことを確かめる。
  - 木でない台帳では、掃引などで穴がないことを確かめる。
  - 面積（体積）の和だけでは十分条件にならない。重なりがあると、和が等しくても穴が残りうる。
  - **重なりは許す。** ただし、重なりの有無と量を記録する。
- **来歴：** 入力の台帳のハッシュを記録し、元の保管物とバイト単位で照合する。
- **移送：** ある辺の台帳を内側へ移すときは、各行の余裕、誤差の式、残りの余裕を、丸める前の分数で残す。

## 5. 監査の基準（GeoEncloseReader）

監査は次の順に行う。

1. **受け取り：**
   - ハッシュを照合する。
   - ZIP は別のディレクトリに展開し、危険なパスを調べる。
   - Python は `-I` で動かし、作った人のスクリプトは写しの上でだけ動かす。
2. **定義への遡り（必須）：** 作った人と監査が同じ指示書の式から出発すると、指示書の誤りが両方に入る。そこで、核が**元の幾何学的な定義**（例：エネルギー E(q) ＝ ⟨k arccos²γ⟩ の数値微分）と一致することを、別の求積で確かめる。
3. **点の照合（必須の第一段）：** 台帳の点の主張（節点の値など）が、独立な値を含むかを全件照合する。安く全件に掛けられ、式や転記の誤りを見つける（例：Claude Code の照合、158,551 点で 25 分）。**点の照合だけでは、箱の値域も分類も確かめたことにならない。**
4. **手による照合：** 新しい解析の補題と定数は、全部を手で追う。定数の連鎖は、監査のコードで数値を再計算する。補題に §1.2 の状態を付ける。
5. **独立な核：** 作った人のコード、核、係数を使わない。式は自分で導き直す。
6. **抜き取り：**
   - 区分は、少なくとも量・核・表示・接触の有無で分ける。
   - 各区分で、**余裕の最も弱い箱を 2 個以上**選ぶ。
   - 各区分で、**固定した種による乱数の箱を 4 個以上**選ぶ。誤った式が大きな余裕を生むこともあるので、乱数の側も必要である。
7. **同じ量の確認：** 箱の中心での自分の包みが、作った人の区間と交わることを確かめる。交わらなければ INCONSISTENT とする。
8. **符号の確認：** 箱の全体で、主張した符号を自分の包みで確かめる。
9. **余裕の予備：** 適応的な分割では、終端の箱の余裕はぎりぎりになる（V57）。これは不正ではなく、仕組みからの帰結である。ただし、核の小さな誤りで符号が崩れうる。そこで、抜き取った最弱の箱について、監査の包みでの余裕が作った人の余裕より小さくならないことを確かめる。小さくなる場合は、1 段細かく分けて余裕が増えることを確かめる。
10. **被覆と移送の再計算：** §4 の検査を、自分のコードで全件行う。

## 6. 根の主張

「零点がちょうど一つ」のような主張は、箱の符号だけでは言えない。次の三つを別々に示す。

1. **存在：** 端で符号が反対になることを示す。または Krawczyk などの包含で示す。
2. **一意性：** 零の候補の上で、導関数の符号を示す（例：零ではいつも下向きに横切る）。
3. **位置：** 区間で包む。

**退化する点**（中心の退化、零が境界に達する点、合流）は別に扱う。局所の解析（四階の項、片側の Hessian など）で、零の個数と指数を示す。

## 7. 採用の基準と水準

### 7.1 採用の共通の条件
1. 作った人の検査器が通る（ハッシュ、整数の被覆、符号、局所の包含）。
2. §5 の監査で CONTRADICTED も INCONSISTENT もない。
3. 新しい解析の補題が、すべて HAND_CHECKED 以上である。
4. **主張と台帳の対応表**がある。計算上の主張を命題（C1、C2、…）として書き、各命題を支える台帳、核、検査を表にする。
5. 主張の範囲と未了の部分が明記されている（§8）。
6. 計画、台帳、コード、記録が evidence に保管されている。

### 7.2 水準
| 水準 | 条件 | 論文での書き方 |
|---|---|---|
| **A1 採用（抜き取り）** | 7.1 と、§5 の抜き取りによる監査 | 計算上の命題 C1、C2、… を**仮定として明示した定理**（「C1〜C6 のもとで…」） |
| **A2 全件の独立再計算** | 7.1 と、全部の終端の箱を独立な核で包み直して CONFIRMED | **無条件の定理**（計算機援用の証明として） |

採用した後で反例や誤りが見つかったら、訂正として記録し、採用を見直す。

### 7.3 公開と人の責任
論文にする段階では、次の二つを加える。
- **公開：** 台帳、コード、計画、検査器を、DOI 付きの公開物にする。
- **人の確認：** 著者本人が最終の確認を行い、主張の範囲と水準に責任を持つ。

## 8. 結果の表記の基準

- **範囲を数で書く。** 例：「1 < s ≤ 1 ＋ 2⁻³⁹」「log(st) ≤ 10⁻⁵」。
- **存在定理と明示的な結果を区別する。** 近傍の大きさが出ていないときは、そう書く。
- **水準（A1 か A2 か）を書く。**
- **未了の部分を同じ表に書く。**
- **言い過ぎない。** 「閉じた」と書くのは、主張の全範囲で §7 を満たしたときだけにする。
- **誤りは訂正として残す。** 番号（E1、E2、…）を付け、元の文を消さない。

## 9. 道具を残す

一つの問題の解答より、次の問題を解くための道具を残す。

- 監査のたびに、核と selftest を GeoEncloseReader に加え、版を上げて保管する。
- 道具の限界と、分かった注意点を README に書く（例：細長い形での赤道の H₃₃）。
- 計算の費用は実測して残す。見積もりは方法に依存するので、どの方法での数かを書く（V58）。
