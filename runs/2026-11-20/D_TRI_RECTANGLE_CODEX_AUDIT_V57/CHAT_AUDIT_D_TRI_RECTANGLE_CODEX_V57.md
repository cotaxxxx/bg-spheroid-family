- **chat の包みは、Codex の包みよりずっと狭かった。** ほとんどの箱は、分割なし、N ＝ 128 の一回の評価で符号が出た（28 箱で合計 163 秒）。例えば、τ の最弱の箱（t ∈ [4.25, 4.375]、r ∈ [0.375, 0.383]）で、Codex の下界は 0.00018、chat の箱の中心での値は 0.0666〜0.0676 である。Codex の終端の箱の区間の多くは、およそ [2c, 0] の形をしている（c は中心の値）。これは、符号がぎりぎり出るまで分割した結果である。

## 5. 評価と、次の一手について

1. **採用できるもの：** 層 IV（主矩形全体での四つの曲線と一つの交点）、明示帯の完全な分類、球の近くの結果、付録 C の二つの排除。chat の推奨は「研究成果として採用する」である。
2. **意味の大きさ：** 内陸の完全な分類はまだない。明示帯と球の近くは、近傍の大きさを数で示したという意味が主である。
3. **計算予算の見積もりについて：** Codex は、層 I を直接覆うには 2.2〜5.4 万 CPU 年かかると見積もった。この見積もりは、Codex の一次の包みでの成功率に基づく。今回、chat の二次の包みは、Codex の終端の箱を分割せずに決めた。つまり、方法を変えれば必要な箱の数は大きく変わりうる。ただし、層 I・II の一般の内部点の核は、まだ誰も二次で書いていない。だから、この差がどこまで効くかは、較正してみないと分からない。
4. **次の一手の候補：**
   - (a) **chat が Reader 0.3.0 を一般の内部点（W₃ と C₁₂）に広げ、Codex の較正のパッチ（cal.csv の 32 形状 × 8 パッチ）で成功率と時間を測る。** 定理は作らない。予算の見積もりを測り直すための道具である。
   - (b) Codex の推奨 1：内陸の一つの細い帯で、層 I・II の縮約を単発で依頼する。
   - (c) Codex の推奨 2：先に全域の軸上の根の数（層 III）だけを求める。
